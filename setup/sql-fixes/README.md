# Собствени SQL поправки

Тук се слагат поправките по света — счупен райд, дънджън, NPC, плячка, спелл.
Файловете **са в git**, така че всяка машина може да ги възпроизведе.

```powershell
.\setup\apply-sql-fixes.ps1 -List    # какво е приложено и какво чака
.\setup\apply-sql-fixes.ps1          # прилага чакащите
```

---

## Защо не се пипа направо базата

`acore_world` не се дъмпва и не е в git — AzerothCore я генерира сама от своите
SQL файлове при първото пускане. Затова ръчна поправка направо в базата:

- не съществува на другата машина
- изчезва и от тази, щом `acore_world` бъде пресъздадена
- никъде не пише какво е било променено и защо

Файл тук решава и трите. Освен това е и обяснение — след шест месеца ще искаш да
знаеш защо си сменил нещо.

---

## Как се пише поправка

Име: `NNN-кратко-описание.sql`, с нарастващ номер. Редът на прилагане е по име.

```sql
-- target: acore_world
--
-- Gunship (ICC 25): заклинанията на оръдията не се виждат.
-- Причина: липсва ред в spell_script_names, затова скриптът не се закача.
-- Проверено на: 2026-08-01

DELETE FROM spell_script_names WHERE spell_id = 69399;
INSERT INTO spell_script_names (spell_id, ScriptName) VALUES
  (69399, 'spell_igb_rocket_pack');
```

**Редът `-- target:` е задължителен**, ако базата не е `acore_world`. Приема се
`acore_world`, `acore_characters`, `acore_auth`, `acore_playerbots`.

### Три правила

1. **`DELETE` преди `INSERT`.** Прилага се по веднъж на машина, но базата може да
   бъде пресъздадена и тогава файлът тръгва пак. Без `DELETE` вторият път дава
   грешка за дублиран ключ и спира всичко след себе си.

2. **Не редактирай приложен файл.** Скриптът пази sha256 и ще предупреди, че
   промяната **не е жива**, вместо да я приложи тихо. Направи нов номер.

3. **Пиши причината, не само промяната.** Какво е било счупено и защо това го
   поправя.

## Обичайният цикъл

```powershell
# 1. намираш и поправяш
notepad setup\sql-fixes\001-icc-gunship-rocket-pack.sql
.\setup\apply-sql-fixes.ps1

# 2. тестваш в играта

# 3. качваш
git add setup\sql-fixes\001-icc-gunship-rocket-pack.sql
git commit -m "fix: ICC gunship rocket pack spell script"
git push
```

На другата машина:

```powershell
git pull
.\setup\apply-sql-fixes.ps1
```

Повечето промени по таблиците на света искат рестарт на `worldserver`, или поне
`reload creature_template` / `reload smart_scripts` от конзолата.

---

## Как се проследява

Всяка приложена поправка се записва в таблица `custom_fix_log` **вътре в базата,
която променя** — нарочно не в обща.

Така, ако `acore_world` бъде изтрита и генерирана наново, дневникът ѝ си отива с
нея и всички поправки по света се прилагат отново — вместо да бъдат тихо
пропуснати, защото някаква външна таблица твърди, че вече са минали.

## Кога това НЕ е верният инструмент

| Промяна | Къде |
|---|---|
| Рейтове, поведение на ботове, брой ботове | `.conf` → `export-settings.ps1` |
| Логика в C++ (AI на ботове, скрипт на бос) | нов `.patch` в `setup\patches\` |
| Акаунти, герои, GM права | не се пренасят през git — виж `MIGRATION.md` |
